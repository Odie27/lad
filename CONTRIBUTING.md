# Contributing to LAD

LAD is a published pattern, and this repository is its home. Contributions
that make the pattern clearer, more checkable, or easier to adopt are
welcome.

## Ways to contribute

- **Implementations** — building on LAD? Add your system to
  [IMPLEMENTATIONS.md](IMPLEMENTATIONS.md) by pull request.
- **Reference code** — ports of the reference ledger/gate to other
  languages, or clarifying improvements to the existing one. Keep them
  minimal and readable; this code teaches the pattern.
- **Principle clarifications** — open an Issue where a principle is
  ambiguous in a real system. Concrete cases improve the pattern more than
  abstract debate.
- **Interoperability notes** — how LAD composes with MCP, A2A, UCP, or
  other protocols in a system you've built.

## Ground rules

- **Claims must be verifiable.** Link to the running system, the code, or
  the document that backs a statement. Unverifiable claims don't merge.
- **LAD is a pattern, not a standard** — yet. Write accordingly: describe
  what implementations do, don't invent conformance requirements. The
  formal specification arrives in Phase 4, with adoption.
- **No marketing copy in the pattern documents.** The principles and
  architecture files describe the layer, not any one product — including
  the reference implementation.

## Process

Small changes: open a pull request directly. Larger proposals (new
documents, changes to the principles): open an Issue first so the shape
can be discussed before the writing.
